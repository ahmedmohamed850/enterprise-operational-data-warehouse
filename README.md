# Enterprise Operational Data Warehouse & Analytics Pipeline

An end-to-end data engineering portfolio project focused on transforming synthetic operational data into a structured enterprise data warehouse for analytics, reporting, and decision support.

## Project Overview

This project simulates operational data generated by a large technical organization, including:

- Equipment and asset records
- Maintenance history
- System performance logs
- Incident and failure records
- Personnel and resource data
- Inventory and spare-parts data
- Procurement records
- Periodic operational reports

The objective is to build a complete data pipeline using Python, PySpark, SQL Server, dimensional data modeling, data quality validation, and business analytics.

## Planned Data Sources

The project uses synthetic data only.

Datasets include:

- equipment.csv
- maintenance.csv
- incidents.csv
- system_logs.csv
- personnel.csv
- inventory.csv
- procurement.csv

No confidential or real operational data is used.

## Data Quality

The pipeline will detect and handle issues such as:

- Missing IDs
- Duplicate records
- Invalid dates
- Negative costs
- Invalid status values
- Missing equipment references
- Invalid foreign keys
- Inconsistent operational records

## Data Warehouse Model

The warehouse will use a dimensional model containing fact and dimension tables.

Example dimensions:

- DimEquipment
- DimDate
- DimLocation
- DimPersonnel
- DimSupplier

Example fact tables:

- FactMaintenance
- FactIncidents
- FactInventory
- FactProcurement

## Business Questions

The analytical layer will answer questions such as:

- Which equipment has the highest failure rate?
- Which assets generate the highest maintenance cost?
- What is the average equipment downtime?
- Which locations experience the most incidents?
- Which spare parts require reordering?
- Which suppliers have the longest delivery times?
- How does operational performance change over time?
